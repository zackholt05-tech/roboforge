## 4. Analysis, fixed now

- **Primary metric:** success before the 400-step horizon (first-success rule); k/n per checkpoint with a Wilson 95 % interval.
- **Uncertainty:** hierarchical paired bootstrap (RESEARCH_PROTOCOL §9), B = 10,000, seed 20261106, 95 % percentile, numpy linear interpolation intervals; draw order states, bc_mlp, bc_rnn, bc_mlp_chunk, diffusion_unet, random_uniform (`roboforge.eval.statistics.hierarchical_paired_bootstrap`). States are resampled once per replicate and shared by every family (pairing by start); each family's seeds are resampled independently. Time steps are never units of analysis.
- **Declared comparisons, per task** (every other difference is exploratory; no p-values, no multiplicity correction):

| Hypothesis | Paired difference (A − B) |
|---|---|
| H1 | bc_mlp − random_uniform |
| H1 | bc_rnn − random_uniform |
| H1 | bc_mlp_chunk − random_uniform |
| H1 | diffusion_unet − random_uniform |
| H2 | diffusion_unet − bc_mlp |
| H2 | diffusion_unet − bc_rnn |
| H2c | diffusion_unet − bc_mlp_chunk |
| H3 | bc_rnn − bc_mlp |

- **Separated / not separated:** separated when the 95 % interval of a paired difference excludes 0; otherwise not separated (reportable, not evidence of equality).
- **Secondary outcome:** censored_episode_length, first-success step if successful, else 400, for H2, H2c, H3, with the same bootstrap.
- **Aggregation:** per task only; no pooled Lift + Can number. Descriptive only: mean first-success step over successful episodes; per-seed values; failure-category counts; latency and training cost.
- **Three kinds of negative result, kept apart.** *Engineering-incomplete*: an evaluation with no summary, fewer than all starts, a failed `verify_record` audit or a non-canonical platform (rerun once only for a fault outside the policy before the summary, §14.6), and episodes labelled `engineering_error` (counted as failures in the primary metric, reported separately). *Task failure*: an episode that reached the horizon without success, labelled by the taxonomy. *Statistical uncertainty*: a declared difference whose interval contains 0 (not separated).
- **If an evaluation is still incomplete after its one rerun:** its family is reported ENGINEERING-INCOMPLETE on that task. Its complete evaluations are listed per checkpoint; the family is left out of that task's bootstrap (the draw order skips it); every declared comparison involving it is reported as not computed; the other declared comparisons are computed as frozen.
- **Failure taxonomy:** `configs/eval/failure_taxonomy.yaml` (SHA-256 `5a5d998f12b16f58457be87edc417eba0f65bc386c8ec1a29f84e829d64bd7f6`), RESEARCH_PROTOCOL §14.5, applied to every held-out episode.
- **Example episodes:** per task and family, among the frozen checkpoints ordered by seed: the first success and the first failure (sorted state_id) of the lowest seed that has one; plus, per failure category, the first episode in (family order, seed, state_id). Rendered only from recorded states, labelled illustration.
- **Outputs:** per-evaluation summaries `reports/session7/heldout/`, records `runs/<eval_run_id>/`; analysis `reports/session7/results/` (`make analyze-final`, `scripts/analyze_heldout.py`), written once.

## 5. RESEARCH_PROTOCOL §14.6, verbatim

### 14.6 Test-analysis items fixed now (repeated verbatim in `docs/FINAL_TEST_FREEZE.md`)
- **R = 1** for the held-out test, as in §6.4 (no repeats are added; KI-028's start/seed
  confound for diffusion remains and is reported).
- **H1 on the test:** the non-learned `random_uniform` policy (policy_seed 0) runs every
  held-out start of each task once, so H1 is a paired comparison on the test states.
- **Declared comparisons, per task** (no pooled Lift + Can number, §9): H1 each family −
  random; H2 diffusion − BC-MLP and diffusion − BC-RNN (primary); H2-c diffusion −
  BC-MLP-chunk; H3 BC-RNN − BC-MLP. Every other difference is exploratory. No p-values and no
  multiplicity correction: intervals are reported for every declared difference.
- **Separated / not separated:** a paired difference is *separated* when its 95 % percentile
  interval (§9 bootstrap) excludes 0, and *not separated* otherwise. "Not separated" is a
  reportable outcome, expected on Lift (KI-034); it is not evidence of equality.
- **Secondary outcome** (declared now for the saturated case): the episode length with
  failures censored at the 400-step horizon (first-success step if successful, else 400),
  defined for every (seed, state) and analysed with the same paired bootstrap. The mean
  first-success step over successful episodes only is reported descriptively, never compared.
- **Engineering reruns:** an evaluation stopped by an engineering fault outside the policy
  (container or host crash, out of disk) before writing its summary is rerun once from
  scratch, with the incident recorded; evaluation is deterministic, so a rerun cannot change
  an outcome. An error raised inside an episode (policy exception, invalid action) is an
  outcome (`engineering_error`), never rerun.
